cng-map-widgets

Composable, zero-build browser widgets for cloud-native geospatial data. Find an area — search a published gazetteer, upload a GeoJSON, draw one — then act on it: filter and download a dataset, or clip a raster.

No API, no server, no build step. Everything runs in the browser against object storage over HTTP range requests. An import map is the entire setup.

See it running → Source on GitHub

Status: experimental. Nothing is published to npm yet. The APIs work and are verified against live data on every change, but they are not frozen. This is place-name and boundary lookup — not address geocoding.

Try it with nothing installed

This is a complete file. Save it anywhere, open it in a browser, and you have a working geocoder over a 52,398-name gazetteer — nothing cloned, nothing built, no package manager. The import map points at this site. 

<!doctype html>
<html lang="en">
<head>
<meta charset="utf-8" />
<link rel="stylesheet" href="https://unpkg.com/maplibre-gl@4.7.1/dist/maplibre-gl.css" />
<script src="https://unpkg.com/maplibre-gl@4.7.1/dist/maplibre-gl.js"></script>
<!-- Map EVERY package you need transitively, not just the one you
     import: these packages cross-import each other by bare specifier
     (@cng/spec especially), and an unmapped specifier is a runtime
     failure. An import map is strict JSON -- a // comment inside this
     block stops it parsing and breaks every import. -->
<script type="importmap">
{
  "imports": {
    "@cng/spec":          "https://cholmes.github.io/cng-map-widgets/packages/spec/src/index.js",
    "@cng/geocoder-core": "https://cholmes.github.io/cng-map-widgets/packages/geocoder-core/src/index.js",
    "@cng/maplibre":      "https://cholmes.github.io/cng-map-widgets/packages/maplibre/src/index.js"
  }
}
</script>
<style>html, body { margin: 0; height: 100%; } #map { position: absolute; inset: 0; }</style>
</head>
<body>
<div id="map"></div>
<script type="module">
import { Geocoder } from '@cng/geocoder-core';
import { GeocoderControl } from '@cng/maplibre';

const map = new maplibregl.Map({
  container: 'map',
  style: 'https://tiles.openfreemap.org/styles/liberty',
  center: [10, 25], zoom: 2,
});

// The live, published geoBoundaries gazetteer: 52,398 named admin units
// across ADM0/1/2, CC-BY-4.0. Static files on object storage -- there is
// no API and no server anywhere in this page.
const geocoder = new Geocoder({
  indexUrl: 'https://data.source.coop/portolan-mirrors/geoboundaries-catalog/names/index.json',
  limit: 8,
  geometry: { resolution: 'both' },
});

geocoder.on('select', ({ result, area }) => {
  console.log(result.name, area.bbox, area.vertexCount.display);
  // `area` is now ready to hand to @cng/download-core.
});

// The control owns the combobox, the outline layer, fitBounds and the
// attribution line. The index is fetched lazily on first focus.
const control = new GeocoderControl({ geocoder, placeholder: 'Search for a place\u2026' });
map.on('load', () => map.addControl(control, 'top-left'));
</script>
</body>
</html>

Do not add hyparquet to that import map. The packages import() it themselves from pinned, exact-version CDN URLs.

Pin it

The URLs above track whatever is on main. For anything you care about, pin a tag through jsDelivr instead — same mechanism, reproducible: 

https://cdn.jsdelivr.net/gh/cholmes/cng-map-widgets@v0.2.0/packages/geocoder-core/src/index.js

Node, or inside a bundler

Honestly worse, until this is on npm. npm i cannot install a subdirectory of a git repo, so there is no way to pull a single @cng/* package from GitHub. Clone the repo and npm link, or vendor the packages/ directory. Then inject hyparquet once, before the first load() — Node has no network imports, and a bundler cannot rewrite the runtime-computed CDN specifier: 

import * as hyparquet from 'hyparquet';
import { compressors } from 'hyparquet-compressors';
import { setHyparquetModules } from '@cng/geocoder-core';

setHyparquetModules({ hyparquet, compressors });

Or clone it

git clone https://github.com/cholmes/cng-map-widgets.git
cd cng-map-widgets
python3 serve.py          # then open http://localhost:8000/examples/
Not python3 -m http.server. It answers a Range request with 200 and the whole file. Nothing errors — every range read silently becomes a full download, which against the 409 MB Overture index looks like a hang rather than a failure. serve.py is a few lines of stdlib that returns 206 properly. npx serve works too.

The packages

The seam that makes these composable is one plain JSON object, the Area. The geocoder emits one, the upload widget emits one, a draw tool could emit one, and the download widget consumes one. Nothing else couples.

PackageWhat it does
@cng/specThe shared contracts — Area, the error taxonomy, the geometry helpers.
@cng/geocoder-corePlace-name search over a published cloud-native gazetteer. Emits an Area.
@cng/upload-coreThe same Area, from a dropped GeoJSON file, with repairs reported.
@cng/download-coreFilters a GeoParquet table, STAC collection or hive catalog to an Area and writes a file.
@cng/raster-coreClips a COG to an Area, with band selection and a size estimate.
@cng/maplibre, @cng/openlayersMap adapters: search control, area layer, viewport provider, antimeridian-aware fit.
@cng/format-*Optional output formats — GeoPackage, Shapefile, FlatGeobuf.
